## 1. Statutory Mandate for Cryptographic Traceability

Under Section 63 of the **Bharatiya Sakshya Adhiniyam, 2023 (BSA)** and Section 8(7) of the **Digital Personal Data Protection Act, 2023 (DPDP)**, automated electronic records used in clinical decision-making must be verifiably auditable.

If a diagnostic suggestion or symptom extraction is contested in a clinical audit or court of law, the health system must reconstruct the exact software configuration that produced the inference.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                 EIGHT MANDATORY VERSIONING ATTRIBUTES                       │
├─────────────────────────┬───────────────────────────────────────────────────┤
│ 1. Model Identifier     │ e.g. qwen3-4b-instruct                            │
│ 2. Model Version        │ Semantic version or release tag (e.g. 1.0.0)      │
│ 3. Quantization Format  │ e.g. Q4_K_M (GGUF 4-bit medium)                   │
│ 4. Runtime Identifier   │ e.g. local_ollama / llama_cpp_server              │
│ 5. Runtime Version      │ Engine version (e.g. ollama-0.3.12 / llama-b3840) │
│ 6. Prompt Template ID   │ e.g. PROMPT_EXTRACTION_V1 (commit sha)            │
│ 7. Config Version       │ Operational environment profile config hash       │
│ 8. Generation Timestamp │ Exact ISO-8601 UTC timestamp                      │
└─────────────────────────┴───────────────────────────────────────────────────┘
```

## 2. Model Configuration Manifest Schema

Every approved model configuration is declared in an immutable manifest:

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "CLINOVAModelManifest",
  "type": "object",
  "required": ["manifest_id", "model_id", "version", "quantization", "weights_sha256", "runtime", "runtime_version", "license"],
  "properties": {
    "manifest_id": { "type": "string" },
    "model_id": { "type": "string" },
    "version": { "type": "string" },
    "quantization": { "type": "string" },
    "weights_sha256": { "type": "string", "pattern": "^[a-f0-9]{64}$" },
    "runtime": { "type": "string" },
    "runtime_version": { "type": "string" },
    "context_window_tokens": { "type": "integer" },
    "ram_budget_mb": { "type": "integer" },
    "license": { "type": "string" },
    "created_at": { "type": "string", "format": "date-time" }
  }
}
```

## 3. Configuration Immutability & Invalidation Rule

$$\mathbf{Changing\ Model\ Weights\ Creates\ a\ New\ Identifiable\ Configuration}$$

1. **No In-Place Overwrites:** Model weights files (`.gguf`) must never be overwritten in-place under the same file name. Every new checkpoint must bear a unique version tag and SHA-256 hash.
2. **Immediate Cache Invalidation:** When the active `model_id` or `model_version` is updated in configuration, all cached inferences generated by prior versions are automatically invalidated.
3. **Forensic Audit Attachment:** Every record written to the `ai_inferences` table stores the immutable tuple `(model_id, model_version, prompt_version, weights_sha256)`.
